# NTPE Delivery Package Policy

Status: Architecture Consolidation Batch 1  
Effective date: 2026-07-15

## Purpose

NTPE uses three explicitly different delivery types. A normal Stage must never
create a complete `NTPE.zip`. GitHub is the daily source of complete history.

## Source Package

The Source Package is the normal execution, installation, and user delivery.
The canonical filename is `dist/NTPE_SOURCE.zip`.

It may contain:

- production Python source and launchers;
- required runtime configuration templates;
- required schemas, rules, profiles, and deterministic fixtures;
- dependency declarations;
- current architecture and operating documentation.

It must not contain:

- `.git`, Git history, or repository metadata;
- `artifacts/`, `audits/`, historical Stage evidence, or Provider responses;
- `tests/literary/outputs/` or complete regression output;
- another ZIP, cache, backup, package staging, log, or temporary output;
- input novels, character-memory/private resume state, local configuration, API
  keys, credentials, secrets, or private-key material.

`tools/package_source.py` builds the formal package from Git tracked files only
(`git ls-files --cached`). Untracked files are excluded by default even when
they match the source allow policy. A special-purpose build may include
non-ignored untracked files only through the explicit `--include-untracked`
opt-in; that mode is reported as `tracked_only=false` and is not the formal
Source Package default.

Every build must resolve Git `HEAD` or fail closed before creating a package.
The tool applies an explicit allow policy, verifies root containment,
normalizes archive names to `/`, rejects secret-bearing paths, and reports Git
HEAD, tracked-only status, entries, SHA-256, integrity, separator compliance,
and Unicode round-trip.

## Audit Package

An Audit Package is a small Stage-acceptance bundle. It may contain only paths
listed in an explicit allowlist manifest, together with their expected SHA-256.

Typical contents are:

- files changed by the Stage;
- focused and Root tests;
- the Stage manifest and release document;
- only the upstream anchors needed to validate the Stage;
- Git status/diff/deletion evidence;
- validator output and package-test reports.

It must never default to the entire worktree. It must not contain `.git`,
secrets, another ZIP, raw Provider responses, unrelated historical artifacts,
or unlisted files. `tools/package_audit.py` rejects traversal, absolute paths,
duplicates, digest mismatches, invalid JSON manifests, and secret material.

## Full Repository Backup

A Full Repository Backup is permitted only for:

- a major freeze;
- a major migration;
- disaster recovery;
- an explicit human request.

It is not generated by normal Stages. Batch 1 intentionally provides no
automatic full-backup tool. Any future implementation must require a visible
`--allow-full-backup` authorization and a separately reviewed inventory.

## Stage delivery rule

Routine delivery produces a Source Package or a small Audit Package. A Stage
must not recreate `NTPE.zip`, recursively package the repository, include
`.git`, or silently widen an allowlist.
